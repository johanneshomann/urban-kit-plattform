# i18n

Two locales (`de` default, `en`) via **next-intl**, always-prefixed URLs
(`/de/...`, `/en/...`). Routing config: `src/i18n/routing.ts`.

## Scope decision (important)

Bilingual is **UI chrome only**:

- Public portal chrome + the legal global (`LegalSettings` — the only Payload
  content with `localized: true` fields)
- Platform/workspace UI, manage area, auth pages

**Project content stays German-only.** Projects, news, events, polls, forum,
etc. have no localized fields and are not translated. The language switcher
(public nav + platform header) swaps the locale segment and preserves the
path.

## Message catalogs

`messages/de.json` + `messages/en.json`, organized by namespace (`nav`,
`auth`, `profile`, `dashboard`, `platform`, `projektDetail`, `manage`,
`modules`, `taxonomy`, …). Both files must stay key-identical.

- Server components: `getTranslations({ locale, namespace })`
- Client components: `useTranslations('namespace')`

## Copy tone

Formal **Sie** everywhere, minimal direct address. German is the source
language; keep EN translations equally formal.

## Payload admin

The admin panel itself is pinned to de/en
(`payload.config.ts` → `i18n.supportedLanguages`), fallback German.

**Collection/global labels are localized too** (`{ en, de }` objects on field
`label`, select `options`, group/array labels and admin descriptions) — DE is
the source language, EN the mirror. This applies to all core collections and
all module collections. Content stored in those collections stays
German-only; only the admin *chrome* (labels/options/tooltips) is bilingual.
When adding a field/option, provide a `{ en, de }` label pair rather than a
bare German string. Shared select options (project fields, Projektphasen) fan
out from central helpers in `src/lib/options/`.
